# Attendance Scanner

Flutter scanner app for attendance admins. It supports:

- Windows and macOS desktop with a hardware QR reader keyboard wedge.
- Android and iOS mobile with the device camera using `mobile_scanner`.
- Admin login against the existing NestJS API.
- Event attendee personal QR check-in.
- Meeting participant personal QR check-in.
- Clean green attendance scanner theme based on the current wireframe tokens.
- Responsive login and scanner layouts for desktop and mobile.
- Light/dark theme switching and English/Khmer language switching.

The request mentioned "desktop app (iOS & Windows)"; iOS is a mobile platform in Flutter. This project targets Android, iOS, Windows, and macOS. Add Linux if needed.

## Setup

Install Flutter, then run:

```bash
cd attendance-scanner
flutter pub get
```

Generate native platform folders if they do not exist yet:

```bash
flutter create . --platforms=android,ios,windows,macos
```

Generate localization and JSON model files:

```bash
dart run build_runner build --delete-conflicting-outputs
flutter gen-l10n
```

## API

The app talks to the existing API under `/api`.

The API endpoint is configured from a Flutter environment define. The login
screen does not allow runtime endpoint editing.

Default base URL in development:

```text
http://localhost:3001/api
```

For Android emulator use:

```text
http://10.0.2.2:3001/api
```

Windows example:

```bash
flutter run -d windows --dart-define=API_BASE_URL=http://localhost:3001/api
```

Seeded admin account:

```text
admin@example.com / password123
```

## Run

## QR Behavior

Desktop mode:

- Focus stays on a scanner input.
- A USB/Bluetooth QR reader sends the code as keyboard text.
- Pressing Enter triggers check-in.

Mobile mode:

- Uses the camera through `mobile_scanner`.
- First detected QR is submitted.

Accepted QR formats:

- Raw check-in code

Personal attendee and meeting participant QR images generated by the API contain
only the raw check-in code. For compatibility with older QR images, the scanner
can still parse full URLs ending in `/attendee-qr/{code}` or
`/participant-qr/{code}`.

For raw codes the app tries event attendee check-in first, then meeting
participant check-in.
